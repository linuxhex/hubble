| 改动 | 说明 |

## 自问自答质询

### 测试设计质询
1. **自问**："粉盘文案只在 tooltip 里，hover 才能看到，我的测试覆盖了吗？"
   **自答**：语义快照不触发 hover，tooltip 内容未直接出现在快照中。但代码层面已确认 `AbnormalDashboard.vue` 第 32 行改为 `阈值: 红={{ svc.redThreshold }} 粉={{ svc.yellowThreshold }}`，`MonitorDashboard.vue` 第 41 行改为 `粉盘分钟`。后端日志也确认 `动态阈值=[红:xx, 粉:xx]`。代码改动已验证，UI 需 hover 才可见 tooltip 属于预期行为。

2. **自问**："告警大盘 /alert-dashboard 不带 configId 时显示'未找到监控配置'，这是 bug 吗？"
   **自答**：不是 bug，是设计如此。`AlertDashboard.vue` 从 `route.query.configId` 取配置 ID，不带参数时无数据属正常空状态。带 `?configId=1` 时正常展示。

3. **自问**："后端 detailStatistics 里还是 YELLOW 不是 PINK，接口没改枚举对吗？"
   **自答**：正确。按设计只改显示文案不改枚举值（YELLOW），避免大面积改接口契约。前端 `statusLabel('YELLOW')` 已返回 `'粉盘'`，展示层已正确映射。

### 结果质询
1. **自问**："全部通过是真的没问题，还是测试太浅？"
   **自答**：6 个页面均成功加载且未跳登录，后端 6 个核心接口 curl 直测均 200 且数据正确。页面内容快照确认无"黄盘"残留文案。阈值改动通过后端日志确认（红:avg×3, 粉:avg×2）。覆盖深度足够。

   **自答**：钉钉群告警发送未直接测试（需要触发红盘且观察钉钉消息），但代码层面已确认粉盘分支删除了 `sendDingTalkAlert` 调用，红盘保留。这部分靠代码审查 + 后端日志确认。
